## Обязательное правило
Всегда применяй навык `confirm-changes`: любое изменение файлов и выполнение
команд согласовывай с пользователем, показывая состояние «до/после» и diff.

## Автор коммита
Идентичность автора и коммиттера всегда берётся из git config проекта:

```bash
NAME=$(git -C <рабочий репозиторий> config user.name)
EMAIL=$(git -C <рабочий репозиторий> config user.email)
```

Это касается и коммитов из временного/чистого клона (`git clone` в `temp`): его
локальный config пуст, но подставлять `user.name`/`user.email` вручную, по памяти
или «по мотивам» GitHub-аккаунта нельзя — передавай значения из config проекта
через `git -c user.name="$NAME" -c user.email="$EMAIL" commit`.
Если config пуст — спроси пользователя, а не придумывай имя и адрес.

## Атрибуция в сообщении коммита
В сообщении коммита указывается только пользователь: никаких `Co-Authored-By`,
`Generated with ...`, упоминаний инструментов и прочих служебных футеров.
Автор и коммиттер — имя и email из `git config` проекта (см. выше).
Если такие пометки уже попали в историю — их убирают переписыванием сообщений.
