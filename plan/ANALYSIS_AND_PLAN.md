# PBIT Analyzer — Анализ и план развития

## 1. Текущее состояние проекта

### Обзор

PBIT Analyzer — desktop-приложение на Python (PyQt6) для анализа файлов шаблонов Power BI (`.pbit`). Приложение распаковывает архив, читает `DataModelSchema` и `Layout` (UTF-16-LE JSON), извлекает метаданные и предоставляет их в GUI с возможностью построения графа зависимостей (lineage) и генерации Excel-отчёта.

### Стек технологий

| Компонент | Технология |

| Язык | Python 3.10+ |
| GUI | PyQt6 6.7.1 |

| Excel | openpyxl 3.1.5 |

| Линтер | ruff 0.6.9 |

## 2. Выявленные проблемы

### 2.1 Архитектурные

| # | Проблема | Серьёзность | Файл |
|---|----------|-------------|------|
| A1 | **God class** — `LayoutExtractor` ~810 строк, 20+ методов | Высокая | `extractors.py` |
| A2 | **Нет моделей данных** — DataFrames с строковыми именами колонок, без typed dict/dataclass | Средняя | Все файлы |
| A3 | **Дублирование данных** — `current_dfs` + `_original_dfs` хранят полные копии DataFrame в памяти | Средняя | `gui.py` |
| A4 | **Хрупкие индексы** — магические числа `[1, 2, 3, 10]` в merge-логике Excel | Средняя | `excel_report.py` |
| A5 | **Нет отмены операции** — `progress_callback` не поддерживает остановку анализа | Низкая | `analyzer.py` |

### 2.2 Качество кода

| # | Проблема | Серьёзность | Файл:Строка |
|---|----------|-------------|-------------|
| C1 | **Debug-артефакты** — хардкоженные ID визуалов в production-коде | Высокая | `extractors.py:982,1028` |
| C2 | **Дублирование в formatters** — `_add_spaces_operators` и `_apply_operator_spacing` почти идентичны | Средняя | `formatters.py` |
| C3 | **Дублированный вызов** — `_format_visual_id` вызывается дважды подряд | Низкая | `extractors.py:944-945` |
| C4 | **Импорт внутри метода** — `Counter` импортируется в теле метода | Низкая | `extractors.py:1067` |
| C5 | **7 ad-hoc скриптов** в `_work/` — вероятно, мёртвый код | Низкая | `_work/test_*.py` |

### 2.3 Пользовательский интерфейс

| # | Проблема | Серьёзность |
|---|----------|-------------|
| U1 | Нет реализованных горячих клавиш (описаны в справке, но не работают) | Средняя |
| U2 | Нет drag-and-drop для файлов .pbit | Низкая |
| U3 | Все стили захардкожены inline CSS | Средняя |
| U4 | Нет поиска/фильтрации по таблицам | Средняя |
| U5 | `_apply_lineage_focus` — 120+ строк, сложная логика | Низкая |

### 2.4 Производительность

| # | Проблема | Оценка влияния |
|---|----------|----------------|
| P1 | `iterrows()` в lineage.py — медленно для больших моделей | Среднее |
| P2 | Все 12 вкладок заполняются одновременно | Среднее |
| P3 | Авто-ширина колонок Excel — O(n×m) | Низкое |
| P4 | Нет пагинации для больших списков визуалов | Низкое |

### 2.5 Тестирование

| # | Проблема | Серьёзность |
|---|----------|-------------|
| T1 | ~25-30% покрытие — критически мало | Высокая |
| T2 | Нет тестов для lineage (обход графа, BFS) | Высокая |
| T3 | Нет тестов для formatters (DAX/SQL) | Средняя |
| T4 | Нет тестов для Excel-отчёта | Средняя |
| T5 | Нет негативных тестов (битые файлы, невалидный JSON) | Средняя |

## 3. Предложения по улучшению (из improvements.md)

Из документа `improvements.md` отмечены следующие идеи (некоторые отмечены "не делать"):

### 3.1 Реализуемые

- Дополнительные данные из DataModelSchema: lineageTag, annotations, description, formatString, sortByColumn, summarizeBy, expressions, partitions
- Дополнительные данные из Layout: filters, config, resourcePackages, displayOption, vcObjects

- Улучшение lineage: визуализация графа (graphviz/pyvis), экспорт PNG/SVG
- Поиск и фильтрация в каждой вкладке
- Экспорт CSV, JSON, HTML
- Контекстное меню (правый клик)
- Статусная строка с информацией о файле
- Фоновая обработка, прогресс-бар с этапами
- Оптимизация lineage (индексы, кэширование)
- Многопоточное извлечение
- Надёжная очистка временных файлов

- Кэширование результатов анализа (pickle)
- Расширенное логирование в файл + GUI-окно логов
- Автоматическое определение кодировки (fallback на бинарный анализ)
- Валидация структуры JSON

### 3.3 Отложенные (пока не делаем)

- Интеграция с Power BI Desktop
- Сравнение двух PBIT файлов
- Плагины
- Автоматическое обновление

## 8. Заключение

Проект находится в рабочем состоянии с базовой функциональностью. Основные направления улучшений:

1. **Безотлагательно:** удалить debug-артефакты, повысить тестовое покрытие
2. **Краткосрочно:** реализовать горячие клавиши, поиск, контекстное меню
3. **Среднесрочно:** расширить извлечение данных, улучшить lineage
4. **Долгосрочно:** рефакторинг архитектуры, новые форматы экспорта

Общая оценка: **34-49 рабочих дней** для реализации всех предложений.
