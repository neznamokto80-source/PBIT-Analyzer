# План: поддержка .pbix в PBIT Analyzer (v2.2.0)

Статус: **на согласование**. Документ описывает только план; код проекта не изменялся.

## 1. Цель и рамки

Добавить чтение файлов `.pbix` (семантическая модель Power BI) в существующее приложение,
не меняя поведение текущего `.pbit`-анализа.

Входит в v2.2.0:

- `.pbix` как второй входной формат (GUI, CLI, библиотека);
- метаданные модели: таблицы, столбцы, меры, вычисляемые столбцы/таблицы, DAX, Power Query (M),
  M-параметры, связи, RLS, OLS, perspectives, статистика хранения;
- модельный lineage (по DAX/M) с фокусом на мерах и таблицах;
- Excel-отчёт: текущие листы + новые, визуальные листы только в `.pbit`-режиме.

Не входит в v2.2.0 (явно вне scope):

- декодирование строк VertiPaq (`get_table` / `iter_table`) — только метаданные;
- `.abf` и `.xlsx` (PowerPivot), хотя `pbixray` их умеет;
- слой отчёта PBIX (визуалы, страницы, закладки, темы) — `pbixray` его не парсит;
- запись/перепаковка файлов, вычисление DAX, подключение к Power BI Service.

## 2. Источник истины: pbixray

Проверено по репозиторию `Hugoberry/pbixray` и PyPI (версия 0.15.5, MIT).

| Аспект | Факт |
|---|---|
| Входы | `.pbix`, `.abf`, `.xlsx` (PowerPivot); **`.pbit` не поддерживается** |
| Выход | `pandas.DataFrame` / список / dict |
| Модель | `tables`, `schema`, `relationships`, `dax_measures`, `dax_columns`, `dax_tables`, `power_query`, `m_parameters`, `rls`, `ols`, `perspectives`, `aggregations`, `statistics`, `size` |
| DMV | 40 свойств `tmschema_*` (`tmschema_columns`, `tmschema_partitions`, `tmschema_measures` и т. д.) |
| Данные | `get_table(name, columns=..., strings_as_categorical=...)`, `iter_table(..., chunk_size=...)` |
| Большие модели | `PBIXRay(path, on_disk=True, temp_dir=...)`, контекстный менеджер, ленивые метаданные |
| Ошибки | `LiveConnectionError`, `NoEmbeddedModelError` (тонкий отчёт без модели) |
| Python | 3.8–3.13; локально у нас 3.14 → нужен spike |
| Бинарные зависимости | `xpress8`, `xpress9`, `xmhuffman` (Cython/wheels) → важно для PyInstaller |

Ключевое следствие: для `.pbix` недоступны листы/визуалы/условное форматирование.
Модельный lineage строится по DAX-зависимостям и связям, визуальные рёбра отсутствуют.

### 4.3 Поток данных

```
path
  -> detect_file_kind(path)          # file_kind.py
       .pbit + DataModelSchema  -> analyze_pbit_file()   (без изменений)
       .pbix + DataModel        -> analyze_pbix_file()
       несовпадение/битый zip   -> FileFormatError (код 3)
  -> analyze_pbix_file()
       PBIXRay(path, on_disk=...)
       PBIXModelExtractor(model).extract_all()
           -> tables_ref, columns, sources, relationships, measures,
              dax, m_parameters, power_query, rls, ols, perspectives,
              statistics, warnings
       build_lineage_edges(dfs)        # существующий модуль, без правок
       build_lineage_directions(...)   # существующий, фокус S…/M…
       build_stats(dfs, extra=...)
       ExcelReportGenerator(..., sheets=SHEETS_ORDER_PBIX)
```

### 4.4 Адаптер DataFrame (главное для lineage)

`DependencyAnalyzer` уже принимает карты имён/номеров, поэтому переиспользуется как есть:

| Ключ | Колонки (как в `.pbit`) | Источник в pbixray |
|---|---|---|
| `tables_ref` | `№ таблицы`, `Имя таблицы`, `Описание` | `tmschema_tables` (порядок модели) |
| `columns` | `№ столбца`, `№ таблицы`, `Таблица`, `Столбец`, `Описание`, `Тип данных`, `Тип значения`, `Формат`, `Сортировка по столбцу`, `Агрегация по умолчанию`, `Формула (если вычисляемый)`, `Зависимости` | `tmschema_columns` + `dax_columns` для формул |
| `measures` | `№ меры`, `№ таблицы`, `Таблица`, `Мера`, `Описание`, `Формула (DAX)`, `Формат`, `Папка отображения`, `Зависимости` | `dax_measures` / `tmschema_measures` |
| `sources` | `№ таблицы`, `Таблица`, `Тип источника`, `Как создается`, `Зависимости` | `tmschema_partitions` + `power_query` |
| `relationships` | `Название связи`, `Откуда`, `Куда`, `Состояние` | `relationships` |
| `dax` (новый) | `Тип объекта`, `№ таблицы`, `Таблица`, `Имя`, `Выражение` | `dax_tables` + `dax_columns` + `dax_measures` |
| `m_parameters` (новый) | `Параметр`, `Описание`, `Выражение`, `Изменён` | `m_parameters` (`ParameterName`, `Description`, `Expression`, `ModifiedTime`) |
| `power_query` (новый) | `Таблица`, `Запрос (M)` | `power_query` |
| `rls` (новый) | `Роль`, `Таблица`, `Фильтр`, `Состояние`, `Описание` | `rls` |
| `ols` (новый) | `Роль`, `Таблица`, `Столбец`, `Область`, `Права` | `ols` |
| `perspectives` (новый) | `Перспектива`, `Тип объекта`, `Таблица`, `Объект` | `perspectives` |
| `statistics` (новый) | `Таблица`, `Столбец`, `Кардинальность`, `Словарь`, `HashIndex`, `DataSize` | `statistics` |

Правила нумерации (совпадают с `.pbit`):

- таблицы: `S1…Sn` в порядке модели;
- столбцы: `A{n}{cc}` (`A101`, `A102`…), как в `DataModelExtractor.extract_columns`;
- меры: `M1…Mm` в порядке модель → таблица → мера.

Формулы форматируются существующими `DAXFormatter.format_measure/format_column/format_table`,
зависимости — `DependencyAnalyzer.find_dependencies()`. Иконки `📊/📋/📐` — те же константы.

### 4.5 Ошибки и частичные результаты

| Ситуация | Поведение |
|---|---|
| файла нет / неверные аргументы | код 2 |
| расширение не `.pbit`/`.pbix` | код 2, понятное сообщение |
| расширение/содержимое не совпали | `FileFormatError`, код 3, подсказка «переименуйте файл» |
| `LiveConnectionError`, `NoEmbeddedModelError` | код 3, текст «в файле нет встроенной модели (Live Connection)» |
| битый zip / ошибка pbixray | код 3, сообщение по-русски, без traceback (traceback — только `--debug`) |
| не прочитался отдельный блок (RLS, OLS, M, statistics) | предупреждение в `dfs["warnings"]`, лог и строка в Excel «Сводка», код 0 |

## 5. Этапы работ

  замер времени и RSS на самой большой модели.

- Выход: короткая записка с фактами (версии, время, RSS, размер бандла) в этом же файле.

## 6. Риски и изменения, требующие отдельного согласования

1. **Python 3.14 vs pbixray 3.8–3.13.** Если импорт/чтение на 3.14 не работает, придётся
   собирать PBIX-путь и EXE на 3.13 (изменение целевой версии сборки) — отдельное решение.
2. **PyInstaller + бинарные колёса.** `xpress8`, `xpress9`, `xmhuffman` требуют
   `hiddenimports`/`collect_dynamic_libs`; возможны ложные срабатывания антивируса и рост
   размера EXE (оценка после spike). Fallback — `--onedir` для GUI.
3. **Обязательная зависимость.** Все пользователи `.pbit` теперь ставят `pbixray`
   (плюс бинарные пакеты). Если это неприемлемо — вернуться к optional extra.
4. **Правки `excel_report.py`.** Добавляется параметр `sheets` и новые ключи. Это
   единственное изменение общего кода; требуется подтверждение, что аддитивный вид ок.
5. **Тесты без CI-покрытия формата.** `D:\pbix` не коммитим → в CI integration-тесты
   пропускаются; часть ошибок парсинга поймается только локально/на релизе.
6. **Ограничение функциональности.** В PBIX-режиме нет визуалов, страниц и условного
   форматирования; в отчёте они отсутствуют, в GUI скрыты. Это не баг, а граница pbixray.
7. **`perspectives`/`aggregations`** в v1 идут только в Excel (лист «Перспективы»),
   без отдельных вкладок GUI — при желании расширяется позже.

## 7. Критерии приёмки

- [ ] `.pbit`-путь: `pytest` зелёный, Excel совпадает с текущим (кроме даты), вкладки GUI прежние.
- [ ] `.pbix` из `D:\pbix`: открывается в GUI и CLI, заполнены таблицы/столбцы/меры/связи/M/RLS/OLS/статистика.
- [ ] Линедж PBIX: фокус `M…`/`S…` даёт upstream/downstream, визуальные узлы отсутствуют.
- [ ] Excel PBIX: листы по 5-му этапу, визуальных листов нет, предупреждения видны в «Статистике».
- [ ] Ошибки: live-connection и битый zip → код 3 и русский текст; неверный формат → код 2/3 без traceback.
- [ ] EXE GUI и CLI собраны с `pbixray`, запускаются, читают `.pbix` на Windows.
- [ ] `ruff` чисто; CI зелёный; README и CHANGELOG обновлены; версия 2.2.0.
- [ ] Замеры spike зафиксированы (время, RSS, размер бандла).

## 8. Допущения (утвердить при ревью)

1. Имя Excel-файла остаётся `pbi_report_<имя>_<timestamp>.xlsx` для обоих форматов.
2. Существующая текстовая вкладка «Статистика» не меняется; для PBIX добавляется
   отдельная табличная «Статистика модели».
3. `--keep-temp` для PBIX — no-op с записью в лог.
4. Порог `on_disk` — 500 МБ, переопределяется флагом `--on-disk` / `--in-memory`.
5. Предупреждения о частичных сбоях показываются в логе GUI и в листе «Статистика»,
   отдельного диалога нет.
6. `requirements.txt` фиксирует точную версию: `pbixray==0.15.5` (как остальные пины).

### Отклонения от плана (по факту API)

1. `model.tables` — не DataFrame, а `StringArray` имён; адаптер приводит к списку.
2. Свойства `tmschema_measures` у `PBIXRay` нет (в README его тоже нет) → меры берутся из `dax_measures`.
3. Пустые выгрузки `pbixray` приходят без колонок (`shape (0, 0)`); адаптер сам создаёт
   DataFrame с нужной схемой, иначе Excel-листы теряли заголовки.
4. `Type`, `DataType`, `SummarizeBy` в `tmschema_columns` — числовые коды TOM;
   добавлены карты в имена как в `DataModelSchema` (`calculated`, `int64`, `double`…).
5. `tmschema_partitions` содержит служебные строки `H$…`; источники строятся из
   `dax_tables` / `power_query`, а не из партиций.
6. `tmschema_tables` содержит только пользовательские таблицы; служебные
   `DateTableTemplate_*` / `LocalDateTable_*` дополнительно отфильтрованы по имени.
7. Вкладка с размерами названа «Статистика хранения» (чтобы не путать с текстовой «Статистика»).
7a. По итогам ревью убраны дублирующие вкладки «DAX» и «Power Query (M)», а из Excel-отчёта
    PBIX удалены листы «DAX» и «Power Query»: выражения уже есть в «Мерах», «Столбцах»
    и «Источниках». Ключи `dfs["dax"]` и `dfs["power_query"]` оставлены для API.
    Пустые разделы PBIX теперь показываются с пометкой «Нет данных».
7b. Меры собираются по всем таблицам модели, включая скрытые (мера на скрытой таблице
    получает «№ таблицы» = «—» и не теряется ни в «Мерах», ни в lineage); покрыто
    тестами на фикстуре со скрытой таблицей.
7c. `.pbit` с `Layout` в папке `Report` (новые версии Power BI Desktop) поддерживается:
    `file_kind` проверяет часть архива по имени файла в любой папке, а `analyzer`
    ищет `DataModelSchema`/`Layout` по всему дереву и предпочитает ближайший к корню.
7d. Убраны вкладка GUI «Перспективы» и лист Excel «Перспективы»: данные остаются
    в `dfs["perspectives"]`, но в интерфейсе и отчёте не выводятся.
7e. Справка собранного EXE ищет документацию в `sys._MEIPASS`, а не на уровень выше
    (иначе `docs/schema_documentation.md` и `docs/CHANGELOG.md` не находились).
8. Добавлены `run_cli.py --self-test` и `run_gui.py --self-test` — без них smoke-проверка
   собранного EXE в CI невозможна (у windowed-сборки нет консоли).
